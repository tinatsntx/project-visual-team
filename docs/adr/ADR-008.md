# ADR-008: Portable Agent Plugins package format

**Status:** Accepted

## Decision

The editable package uses a root `plugin.json` with the Agent Plugins schema;
OpenAI-specific presentation, `.app.json` mappings, and hook settings live
under `extensions.com.openai`. Skills are discovered from `skills/` and MCP
servers from `mcp.json` per the portable spec.

For native Codex 0.149.0 and desktop-bundled 0.154.0-alpha.6.2, a build script
generates a separate Legacy install root. It contains only
`.codex-plugin/plugin.json` as its manifest entry point, plus `.mcp.json`,
`.app.json`, a whole `hooks/` directory with `hooks/hooks.json` declared by
the manifest, a root `hooks.json` compatibility copy, skills, assets, and hook
scripts derived from the portable source. The generated `.mcp.json` translates
portable `streamable-http` entries to Legacy `http`; the source remains
unchanged. The compatibility root must not contain the portable root
`plugin.json`.

## Rationale

The portable layout is the forward-compatible format, but the tested native
loaders skip AgentPlugin apps and hooks. Generating the Legacy distribution
avoids maintaining independently edited manifests while selecting the loader
that discovers those resources. The manifest-declared `hooks/hooks.json` is
deterministic on pinned loaders, its directory copy covers their default hook
location, and the root `hooks.json` copy is deliberate version-drift insurance
for real-plugin conventions on untraced native versions.

## Consequences

- All extension paths are relative to the plugin root and start with `./`.
- `plugin/` remains the sole editable source; generated compatibility artifacts
  and Codex installed caches are never hand-edited.
- Before native acceptance, disable or do not simultaneously enable
  `visual-team@personal`: duplicate enabled plugins would register the same
  MCP server name and could double-deliver `PostToolUse`, contaminating the
  event-count observation.
